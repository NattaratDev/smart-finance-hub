# Smart Finance Hub (SFH) – ศูนย์กลางการเงินการคลังดิจิทัล
กองคลัง เทศบาลเมืองศรีสัชนาลัย · Phase 1 (ระบบแกนกลาง) + โมดูลงานสารบรรณอิเล็กทรอนิกส์

ระบบตัวอย่างสำหรับสอนการสร้าง WebApp แบบ CRUD + Role & Permission ด้วย **HTML + Supabase + GitHub Pages**

| ไฟล์ | หน้าที่ |
|---|---|
| `database.sql` | สร้างตาราง ฟังก์ชัน RLS Storage และข้อมูลตัวอย่าง (รันครั้งเดียวจบ / รันซ้ำได้) |
| `module_saraban.sql` | โมดูลงานสารบรรณอิเล็กทรอนิกส์ (รัน **ต่อจาก** `database.sql` / รันซ้ำได้) |
| `module_payroll.sql` | โมดูลสลิปเงินเดือน (รัน **ต่อจาก** `database.sql` / รันซ้ำได้) |
| `module_calendar.sql` | โมดูลปฏิทินกองคลัง (รัน **ต่อจาก** `module_saraban.sql` / รันซ้ำได้) |
| `module_travel.sql` | โปรแกรมคำนวณค่าใช้จ่ายไปราชการ/ไปฝึกอบรม (รัน **ต่อจาก** `database.sql` / รันซ้ำได้) |
| `module_register.sql` | ทะเบียนคุมต่าง ๆ: ทะเบียนคุมเบิกค่าเช่าบ้าน (รัน **ต่อจาก** `module_payroll.sql` / รันซ้ำได้) |
| `module_register_tuition.sql` | ทะเบียนคุมเบิกค่าเล่าเรียนบุตร (รัน **ต่อจาก** `module_register.sql` / รันซ้ำได้) |
| `module_register_insurance.sql` | ทะเบียนคุมครุภัณฑ์ (ประกันภัย ภาษีรถ การเบิกน้ำมันเชื้อเพลิง) รถยนต์ อาคารและทรัพย์สิน (รัน **ต่อจาก** `module_register_tuition.sql` / รันซ้ำได้) |
| `module_procurement.sql` | งานจัดซื้อจัดจ้าง วงเงินไม่เกิน 5,000 บาท (รัน **ต่อจาก** `module_register_insurance.sql` / รันซ้ำได้) |
| `module_security.sql` | ฟังก์ชันที่ตรวจ session token + สิทธิ์ สำหรับจัดการผู้ใช้ / Role / สิทธิ์ / หน่วยงาน / โมดูล / เมนูสาธารณะ / ตั้งค่า / Audit Log (รัน **หลังสุด** / รันซ้ำได้ · **จำเป็น** สำหรับหน้าเว็บรุ่นปัจจุบัน) |
| `module_security_lockdown.sql` | ปิดการเข้าถึงตารางแกนกลางโดยตรง (ข้อมูลผู้ใช้ / สิทธิ์ / ตั้งค่า / Audit Log) และปิดการตั้งรหัสผ่านโดยไม่ตรวจสิทธิ์ (รัน **ต่อจาก** `module_security.sql` / รันซ้ำได้) |
| `module_security_rollback.sql` | ย้อนผล lockdown กรณีฉุกเฉินเท่านั้น (ระบบจะกลับเป็นแบบไม่ปลอดภัยชั่วคราว) |

> **ลำดับการรัน SQL:** `database.sql` → `module_saraban.sql` → `module_payroll.sql` → `module_calendar.sql` → `module_travel.sql` → `module_register.sql` → `module_register_tuition.sql` → `module_register_insurance.sql` → `module_procurement.sql` → `module_security.sql` → `module_security_lockdown.sql`
> อัปเดตจากรุ่นก่อน: รัน `database.sql` ซ้ำ 1 ครั้ง (เพิ่มระบบ session token) แล้วรัน `module_payroll.sql` · ผู้ใช้ที่ Login ค้างไว้จะต้อง Login ใหม่ 1 ครั้ง

## ทะเบียนคุมต่าง ๆ (register) – ทะเบียนคุมเบิกค่าเช่าบ้าน
ข้อมูลส่วนบุคคล → **บุคคลทั่วไปมองไม่เห็น** · ตาราง `rent_*` อ่าน/เขียนผ่านฟังก์ชัน `sfh_rent_*` ที่ตรวจ session token + สิทธิ์ `register.manage_rent` เท่านั้น (แบบเดียวกับสลิปเงินเดือน) · ทุกการบันทึก/ลบ/พิมพ์/ส่งออก อยู่ใน Audit Log

| แท็บ | ใช้ทำอะไร |
|---|---|
| ทะเบียนคุม | ตารางผู้มีสิทธิ์ × 12 เดือน (ต.ค.–ก.ย.) ตามปีงบประมาณ · กดช่องเดือนเพื่อบันทึกการเบิก · "บันทึกประจำเดือน" ทีละหลายคน · **เลือกดูรายคน** (ช่องเลือกชื่อ / ลิงก์ "ดูรายคน"): ข้อมูลสิทธิ์ สิทธิ์เบิกทั้งปี เบิกแล้ว คงเหลือ และตาราง 12 เดือน (เลขที่ฎีกา วันที่วางฎีกา สถานะ) · เลื่อนคนก่อน/คนถัดไป · รีเฟรชแล้วอยู่ที่คนเดิม · พิมพ์/PDF: ทะเบียนรวม (A4 แนวนอน), รายบุคคล (A4 แนวตั้ง คนละหน้า), รายงานประจำเดือน — เลือกพิมพ์ **ทุกคน หรือเลือกรายคน** (ติ๊กได้หลายคน ค้นหาชื่อ เลือกทั้งหมด/ล้าง) · Excel |
| ผู้มีสิทธิ์ | รายชื่อผู้มีสิทธิ์ทั้งหมดของปีงบ (ช่วงสิทธิ์ ประเภทบ้าน สิทธิ์/เดือน สัญญา คำสั่ง ยอดเบิก) · กรองสัญญาใกล้หมด/สิ้นสุดสิทธิ์ · แก้ไขสิทธิ์หรือข้อมูลบุคลากรได้ทันที |
| บุคลากร | ดึงรายชื่อข้าราชการ (ส่วนท้องถิ่น/ครู) จากสลิปเงินเดือนงวดล่าสุด หรือเพิ่มเอง · ระบุประเภท/ระดับตำแหน่ง และขั้นหรือเงินเดือน → ระบบหาอัตราตามบัญชีให้ |
| บัญชีอัตรา | บัญชีอัตราค่าเช่าบ้าน (แก้ไขถึงฉบับที่ 5 พ.ศ. 2565) · แก้ไขได้โดย `register.manage_rates` |

- **การแก้ไขข้อมูลเดิม** (สิทธิ์ / บุคลากร / รายการเบิก) ต้องยืนยันอีกครั้ง โดยระบบแสดงเฉพาะช่องที่เปลี่ยน (ค่าเดิม → ค่าใหม่) ก่อนบันทึก
- เบิกได้เดือนละไม่เกิน **min(อัตราตามสิทธิ์, ค่าเช่าจริง)** · เดือนแรก/เดือนสุดท้ายของสิทธิ์ ระบบเสนอยอดตามส่วนจำนวนวัน · ฐานข้อมูลปฏิเสธยอดเกินสิทธิ์และเดือนที่อยู่นอกช่วงสิทธิ์
- **สิทธิ์:** Super Admin / Org Admin ได้อัตโนมัติ · เจ้าหน้าที่การเงินที่ดูแลทะเบียน ให้สิทธิ์ `register.manage_rent` รายบุคคลที่ "จัดการผู้ใช้งาน > สิทธิ์"

## ทะเบียนคุมต่าง ๆ – ทะเบียนคุมเบิกค่าเล่าเรียนบุตร
ระเบียบ มท. ว่าด้วยเงินสวัสดิการเกี่ยวกับการศึกษาบุตรของ อปท. พ.ศ. 2563 · อัตราตามหนังสือกรมบัญชีกลาง ว 257/2559 · สิทธิ์ `register.manage_tuition` (Super Admin / Org Admin ได้อัตโนมัติ) · ความปลอดภัยแบบเดียวกับทะเบียนค่าเช่าบ้าน

| แท็บ | ใช้ทำอะไร |
|---|---|
| ทะเบียนคุม | เลือก **ปีการศึกษา** · บุตร × ภาคเรียน 1 / 2 / รายปี พร้อมเพดานและคงเหลือ · พิมพ์/PDF: ทะเบียนรวม, รายบุคคล, รายงานประจำเดือน และสรุปปีงบประมาณ (ตามวันที่วางฎีกา) — เลือกพิมพ์ **ทุกคน หรือเลือกรายคน** (ติ๊กได้หลายคน ค้นหาชื่อ เลือกทั้งหมด/ล้าง) · Excel |
| ผู้มีสิทธิ์และบุตร | บุคลากรชุดเดียวกับทะเบียนค่าเช่าบ้าน (ดึงจากสลิปเงินเดือน) · ข้อมูลคู่สมรส/ผู้ใช้สิทธิ์ (บิดา/มารดา) · ข้อมูลบุตร (วันเกิด ลำดับบุตร บุตรแทนที่) |
| บัญชีอัตรา | 33 รายการ (รัฐ / เอกชนสามัญ / ปวช. 8 สาขา / ปวส.-ปวท. / ปริญญาตรี) · แก้ไขได้โดย `register.manage_rates` |

- ฐานข้อมูลตรวจ: ยอดเบิก ≤ ที่จ่ายจริง (หรือ **ครึ่งหนึ่ง** สำหรับเอกชน ปวส./ปวท./ปริญญาตรี) − ส่วนที่คู่สมรสได้รับแล้ว · ยอดสะสม **ทั้งปีการศึกษา** ≤ อัตรา · ห้ามบันทึกภาคเรียนซ้ำ
- แจ้งเตือน (ไม่บังคับ): อายุบุตรนอกเกณฑ์ 3–25 ปี ณ วันเปิดปีการศึกษา, บุตรลำดับที่เกิน 3 (เว้นแต่บุตรแทนที่), คู่สมรสเป็นข้าราชการ, วางฎีกาเกิน 1 ปีนับแต่วันเปิดภาคเรียน
- แก้ไขข้อมูลเดิมต้องยืนยันอีกครั้ง (แสดงค่าเดิม → ค่าใหม่)

## ทะเบียนคุมต่าง ๆ – ทะเบียนคุมครุภัณฑ์ (เดิมชื่อ ทะเบียนคุมประกันภัย)
สิทธิ์ `register.manage_insurance` (Super Admin / Org Admin ได้อัตโนมัติ – เปลี่ยนเฉพาะชื่อที่แสดง, key/ตารางเดิม) · ความปลอดภัยแบบเดียวกับทะเบียนอื่น (RPC `sfh_ins_*` + Audit Log)

| แท็บ | ใช้ทำอะไร |
|---|---|
| ใกล้หมดอายุ (แท็บแรก) | กรมธรรม์ที่จะหมดภายใน 60 วันและยังไม่ต่ออายุ, หมดอายุแล้ว, ช่วงที่ไม่มีความคุ้มครอง และทรัพย์สินที่ยังไม่มีกรมธรรม์ · รวมรถที่ภาษีใกล้ครบกำหนด/ขาดต่อ |
| กรมธรรม์และภาษีรถ | รวมทะเบียนกรมธรรม์กับภาษีรถไว้ในแท็บเดียว · ทรัพย์สินแต่ละรายการ (ยุบ/ขยาย) แสดงสถานะความคุ้มครองแยก พ.ร.บ. / ภาคสมัครใจ / อัคคีภัย-ทรัพย์สิน / อื่น ๆ และ (เฉพาะรถ) สถานะภาษีในแถวเดียวกัน · ขยายแถวรถเพื่อดูกรมธรรม์ทุกฉบับ + ประวัติการต่อภาษี · ต่ออายุกรมธรรม์จากฉบับเดิมได้ในคลิกเดียว · ปุ่ม "ต่อภาษี" สร้างรายการปีถัดไป (วันสิ้นอายุ +1 ปี, ค่าภาษีเท่าเดิม) · สถานะภาษี: ภาษีปกติ / ใกล้ครบกำหนด (90 วัน – ชำระล่วงหน้าได้) / ภาษีขาดต่อ / ยังไม่มีข้อมูล · บันทึกวันที่ชำระ (บังคับกรอก) ค่าภาษี เลขที่ใบเสร็จ วันตรวจสภาพ (ตรอ.) และฎีกา · กรองประเภท/สถานะ (มีตัวกรอง "ภาษีรถ: ใกล้ครบกำหนด/ขาดต่อ/ไม่มีข้อมูล") · ค้นหาเลขที่กรมธรรม์หรือเลขที่ใบเสร็จภาษีได้ · พิมพ์/PDF รวมรายงานกรมธรรม์และภาษีรถไว้ในเมนูเดียว · Excel |
| น้ำมันเชื้อเพลิง | บันทึกประวัติการเบิกน้ำมันของรถ/ครุภัณฑ์ (ไม่รวมอาคาร): วันที่ เลขที่ใบเบิก ชนิดน้ำมัน ลิตร ราคาต่อลิตร จำนวนเงิน (ลิตร × ราคา แก้ตามใบเสร็จได้) เลขไมล์ ผู้เบิก/พนักงานขับรถ ใช้ในราชการ/เส้นทาง สถานีบริการ ใบเสร็จ ฎีกา และหมายเหตุ (แสดงในรายการ ค้นหาได้ พิมพ์และ Excel) · ระยะทาง = เลขไมล์ − เลขไมล์ครั้งก่อน, กม./ลิตร = ระยะทาง ÷ ลิตรที่เติม (เติมเต็มถังทุกครั้ง) · เตือนเมื่อเลขไมล์น้อยกว่าครั้งก่อน · ดูรายเดือน แยกรายคัน (ยุบ/ขยาย) · พิมพ์/PDF: รายงานการใช้น้ำมันประจำเดือน (สรุปรายคัน), ทะเบียนคุมการเบิกน้ำมัน (รายการ/รายคัน), สรุปปีงบประมาณรายเดือน, **สรุปการใช้น้ำมันแยกตามกอง** (เลือกทุกกองหรือกองเดียว · รายเดือนหรือทั้งปีงบ · กอง → ทะเบียน - ผู้รับผิดชอบ → วันที่เบิก ประเภทน้ำมัน ลิตร บาท พร้อมยอดรวมรายคัน/รายกอง; กอง = "หน่วยงานที่รับผิดชอบ" ของรถ) · Excel |
| ทรัพย์สิน | รถยนต์/ยานพาหนะ (ทะเบียน ยี่ห้อ เลขตัวถัง เลขเครื่อง) อาคาร และทรัพย์สินอื่น · เลขครุภัณฑ์ หน่วยงานรับผิดชอบ · ชื่อ-สกุล ผู้รับผิดชอบ (แสดงในทะเบียนและรายงาน, ค้นหาได้) · "เลิกใช้" = หยุดแจ้งเตือน |
| การเคลม | วันที่เกิดเหตุ ความเสียหาย เลขที่เคลม ค่าเสียหายที่เรียกร้อง/บริษัทจ่าย และสถานะ |

- เบี้ยประกันพร้อมเลขที่ฎีกา/วันที่วางฎีกา · พิมพ์/PDF: ทะเบียนกรมธรรม์ปัจจุบัน, รายการที่ต้องต่ออายุ, สรุปเบี้ยประกันปีงบประมาณ, ทะเบียนคุมภาษีรถ, รายการรถที่ต้องต่อภาษี, สรุปค่าภาษีรถปีงบประมาณ, **ค่าใช้จ่ายจ่ายล่วงหน้า (เบี้ยประกัน) ณ 30 ก.ย.** (จำนวนวันที่กรมธรรม์คงเหลือหลังสิ้นปีงบ · จ่ายล่วงหน้า = เบี้ยประกัน × วันคงเหลือ ÷ วันทั้งหมด · ไม่รวมภาษีรถ) · Excel (แผ่นงานกรมธรรม์ + ภาษีรถ + น้ำมันเชื้อเพลิง)
- เตือนเมื่อช่วงคุ้มครองของกรมธรรม์ประเภทเดียวกันซ้อนกัน และเมื่อวันที่เกิดเหตุอยู่นอกช่วงคุ้มครอง · แก้ไขข้อมูลเดิมต้องยืนยัน (เดิม → ใหม่)

## งานจัดซื้อจัดจ้าง วงเงินไม่เกิน 5,000 บาท (procurement)
ทุกคนใช้ได้ · **บุคคลทั่วไป** เก็บข้อมูลในเบราว์เซอร์ของตนเอง · **เจ้าหน้าที่** (`procurement.save`) บันทึกในระบบของหน่วยงานผ่าน RPC `sfh_proc_*` + Audit Log · โครงการเก็บ **3 เดือน** นับจากแก้ไขล่าสุด (ลบอัตโนมัติ) · ร้านค้าเก็บจนกว่าจะลบ · วงเงินรวมเกิน 5,000 บาท บันทึกไม่ได้ (ตรวจทั้งหน้าเว็บและฐานข้อมูล)

| ส่วน | รายละเอียด |
|---|---|

- **Template เอกสาร** (ปุ่ม "Template"): ข้อความทุกย่อหน้าแก้ไขได้ ใส่ตัวแปร `{ชื่อตัวแปร}` (ชื่อหน่วยงาน ร้าน ยอดเงิน วันที่ เลขที่ ฯลฯ — คำ ซื้อ/จ้าง สลับให้อัตโนมัติ) · เพิ่ม/ลบ/สลับบล็อก ย่อหน้า จัดวาง ตัวหนา ขนาด ระยะห่าง · หัวบันทึกข้อความ ตราครุฑ ตาราง และช่องลงนาม มีรูปแบบตายตัว · ตัวอย่างด้านขวาแสดงตามร่างทันที
  - **Template ของหน่วยงาน** แก้ได้เฉพาะ Org Admin (`procurement.manage_templates`) · บันทึกเป็นฉบับใหม่พร้อมหมายเหตุ ผู้แก้ วันที่ (ตาราง `proc_templates`) · ผู้ใช้อื่น (เจ้าหน้าที่/บุคคลทั่วไป) **แก้ได้เฉพาะข้อความของโครงการตนเอง**
  - **โครงการจำฉบับที่ใช้** — เปิดย้อนหลังข้อความไม่เปลี่ยน · เปลี่ยนเป็นฉบับล่าสุด/ฉบับใดก็ได้จากประวัติ · คืนค่ามาตรฐานรายฉบับ · คืนฉบับเก่าเป็นฉบับใหม่
  - **กล่องลายมือชื่อ** เพิ่มได้หลายกล่องและเลื่อนลำดับได้ · แต่ละกล่อง: ซ้าย/ขวา (ซ้ายตามด้วยขวา = แถวเดียวกัน, กล่องขวาอยู่แนวเดียวกันทั้งฉบับ) · ความเห็น (เช่น - เห็นชอบ) · บรรทัดลงชื่อ · ชื่อ และ**ตำแหน่งพิมพ์เอง** (หลายบรรทัด/ใช้ตัวแปรได้ เช่น `{ผ่าน1}` · ชื่อว่าง = เส้นจุด) · ซ่อนถ้าว่าง (จำนวนผู้ลงนามยืดหยุ่น) · Template เดิมแปลงเป็นกล่องลายมือชื่ออัตโนมัติเมื่อเปิดตัวแก้ไข
  - กล่องลายมือชื่อมีตัวเลือก **"ใช้ข้อมูลผู้ลงนามจากข้อ 1.4"** (ผู้อนุมัติ, เจ้าหน้าที่พัสดุ, ผ่านขั้นที่ 1–5 ฯลฯ) ใส่ตัวแปรชื่อ/ตำแหน่งให้อัตโนมัติ · ถ้าชื่อเป็นตัวแปรบุคคลแต่ช่องตำแหน่งว่าง เอกสารใช้ตำแหน่งจากข้อ 1.4 (ผู้อนุมัติ = ตำแหน่ง + บรรทัดเพิ่มเติม)
  - **ข้อ 1.4 เจ้าหน้าที่ / ผู้อนุมัติ แสดงช่องกรอกตาม Template ที่โครงการใช้:** ขั้น "ผ่าน" แสดงครบตามที่ Template อ้างถึง (`{ผ่าน1}`–`{ผ่าน5}`, เว้นว่างได้ = ซ่อนกล่องนั้น) · ตัวแปรที่ Template ใช้แต่ไม่มีในแบบฟอร์ม (เช่น `{ชื่อกรรมการ1}`) มีช่อง "ข้อความเพิ่มเติมตาม Template" ให้กรอกรายโครงการ (ไม่กรอก = เส้นจุด)
  - **แก้ข้อความเฉพาะโครงการ** (ทุกคน) ไม่กระทบ template กลาง · เลิกใช้ได้ · เลือกใช้ฉบับใดจากประวัติกับโครงการได้ทุกคน (คืนฉบับเก่าเป็นฉบับใหม่ได้เฉพาะ Org Admin)
- ถ้อยคำในเอกสารเป็นแบบทั่วไปตาม พ.ร.บ.การจัดซื้อจัดจ้างฯ พ.ศ. 2560 และระเบียบกระทรวงการคลังฯ พ.ศ. 2560 **ควรตรวจทานกับแบบฟอร์มที่หน่วยงานใช้จริงก่อนใช้งาน** (แก้ไขต่อได้ในไฟล์ Word)

## โปรแกรมคำนวณค่าใช้จ่ายไปราชการ (travel)
เครื่องคำนวณ **ไม่บันทึกข้อมูลผู้เดินทางหรือผลการคำนวณ** · บุคคลทั่วไปใช้ได้ · พิมพ์ "สรุปการคำนวณ" A4 ได้ (ยังไม่ใช่แบบฟอร์มเบิกจ่าย)

| แท็บ | ใช้ทำอะไร |
|---|---|
| คำนวณค่าใช้จ่าย | เลือก **ไปราชการ** (เบี้ยเลี้ยง + ที่พัก + พาหนะ + อื่น ๆ) หรือ **ไปฝึกอบรม** (+ ค่าลงทะเบียน, หักมื้ออาหารที่ผู้จัดเลี้ยง, กรณีผู้จัดจัดที่พักให้) · คนเดียวหรือหมู่คณะ แสดงยอดรายคน/รวม พร้อมวิธีคิดทุกบรรทัด |
| คำนวณด่วน | คิดเบี้ยเลี้ยง / ค่าที่พัก / ค่าพาหนะ แยกกัน |
| อัตราที่ใช้ / ตั้งค่าอัตรา | ทุกคนดูอัตราได้ · Super Admin / Org Admin (`travel.manage_rates`) แก้ไข สร้างชุดใหม่ (กำหนดวันที่มีผล) และลบได้ |

- อัตราเริ่มต้นตามบัญชีหมายเลข 1–2 ของระเบียบ มท. พ.ศ. 2555 (แก้ไขถึงฉบับที่ 4 พ.ศ. 2561) แบ่ง 3 กลุ่มตำแหน่ง (ก / ข / ค)
- กฎที่เขียนไว้: นับวันเบี้ยเลี้ยง (พักแรม/ไม่พักแรม), หมู่คณะกลุ่ม ก พักรวมเบิกอัตราห้องคู่ (เว้นแต่มีเหตุจำเป็น), วิธีเบิกค่าที่พักเหมือนกันทั้งคณะ, ท้องที่ค่าครองชีพสูงเพิ่มเพดานไม่เกิน 25%, หัวหน้าคณะกลุ่ม ค เช่าห้องประสานงานเพิ่ม
- ⚠️ ค่าเริ่มต้นที่ **ไม่มีในไฟล์อัตรา** (ตรวจสอบก่อนใช้จริง แก้ได้ที่หน้าตั้งค่าอัตรา): กฎนับวัน 24/12/6 ชม., รถยนต์ส่วนตัว 4 บาท/กม., จักรยานยนต์ 2 บาท/กม., ฝึกอบรมหักเบี้ยเลี้ยงมื้อละ 1/3
- ระบบเลือกชุดอัตราที่มีผล ณ วันออกเดินทางให้อัตโนมัติ

## โมดูลปฏิทินกองคลัง (calendar)
ให้ทุกคน (รวมบุคคลทั่วไปที่ไม่ได้เข้าสู่ระบบ) เห็นความเคลื่อนไหวของหน่วยงาน · การ์ด **"ความเคลื่อนไหวกองคลัง"** แสดงบนหน้าแรกและแดชบอร์ด

| ประเภท | ข้อมูลที่บันทึก |
|---|---|
| กิจกรรม | ชื่อ, ประเภท (ประชุม/อบรม/งานพิธี/กำหนดส่ง), วันเวลา, สถานที่, ผู้เข้าร่วม |
| งานมอบหมาย | ชื่องาน, ผู้มอบหมาย/ผู้สั่งการ, ผู้รับผิดชอบ (หลายคน), กำหนดส่ง, ความสำคัญ, สถานะ + ประวัติความคืบหน้า |
| รักษาราชการแทน | ตำแหน่ง, ผู้ดำรงตำแหน่ง, ผู้รักษาราชการแทน, ช่วงวันที่, เลขที่คำสั่ง (เตือนเมื่อช่วงวันที่ซ้อนกัน) |
| ไม่อยู่ปฏิบัติงาน | ชื่อ, ลา / ไปราชการ / อบรม, ช่วงวันที่, ครึ่งวันเช้า/บ่าย · **การลาไม่บันทึกประเภทหรือเหตุผล** (ฐานข้อมูลล้างช่องสถานที่ให้อัตโนมัติ) |

- ทุกรายการเชื่อมกับหนังสือ/คำสั่งในงานสารบรรณได้ (บุคคลทั่วไปเห็นไฟล์เฉพาะเอกสารระดับ "สาธารณะ")
- **สิทธิ์:** guest/ทุกคน = `calendar.view_public` · staff = เพิ่ม/แก้ไข/ลบรายการที่ตนเองบันทึก และอัปเดตสถานะงานที่ตนเป็นผู้รับผิดชอบ · org_admin = `calendar.manage_all` (แก้ไขได้ทุกรายการในหน่วยงาน)
- ข้อมูลตัวอย่าง (ไม่บังคับ): วาง `set sfh.seed_demo = 'on';` ไว้บรรทัดแรกก่อน Run `module_calendar.sql` · ฐานข้อมูลจริงไม่ต้องใช้

## โมดูลสลิปเงินเดือน (payroll)
**ขั้นตอน:** นำเข้าไฟล์ Excel → ระบบอ่านและตรวจสอบ → สลิป → ค้นหา/ดูตัวอย่าง → พิมพ์ A4 หรือบันทึก PDF

1. **นำเข้า** (เมนูสลิปเงินเดือน › นำเข้าไฟล์ Excel) – ลากไฟล์ "รายละเอียดผู้มีสิทธิรับเงินแนบท้ายประกอบ (งด.2)" มาวาง (ฝ่ายประจำ + ฝ่ายการเมือง พร้อมกันได้)
   - ระบบอ่านเดือน/ปี กลุ่มบุคลากร ชื่อหน่วยงาน และทุกชีต (1 ชีต = 1 งาน) ให้เอง **ไม่ต้องจับคู่คอลัมน์**
   - ไฟล์ถูกอ่านในเบราว์เซอร์ **ไม่อัปโหลดไฟล์ต้นฉบับขึ้นเซิร์ฟเวอร์**
2. **ตรวจสอบ** (อัตโนมัติ)
   - 🔴 ต้องแก้: ผลรวมรายการรับ/หัก ≠ ช่องรวม, รับสุทธิ ≠ รวมรับ − รวมหัก, ยอดรวมทุกคน ≠ แถว "รวมทั้งสิ้น", ตัวเลขผิดรูปแบบ
   - 🟡 ข้อสังเกต: รับสุทธิ ≤ 0, ชื่อซ้ำ, เทียบงวดก่อน (คนใหม่ / คนที่หายไป / รับสุทธิเปลี่ยนเกิน 20%)
3. **สถานะงวด:** ร่าง → เผยแพร่ → ปิดงวด (ปิดแล้วนำเข้าซ้ำ/ลบไม่ได้ · เปิดใหม่ได้เฉพาะ Super Admin) · นำเข้าเดือนเดิมซ้ำ ระบบถามก่อนแทนที่
4. **จัดทำสลิปแบบ Manual** (กรณีสลิปจากไฟล์ผิดพลาด) – ในหน้างวด สำหรับผู้มีสิทธิ์ `payroll.manage` และงวดที่ยังไม่ปิด
   - **แก้ไขสลิป** (ไอคอนดินสอ): แก้ชื่อ/ประเภท/หน่วยงาน และรายการรับ-หัก (เพิ่ม/ลบ/แก้จำนวน) ระบบคำนวณยอดรวมให้เอง
   - **เพิ่มสลิป (Manual)**: สำหรับผู้มีสิทธิ์ที่ไม่มีในไฟล์ · **ลบสลิป**: กรณีรายชื่อซ้ำ/ไม่มีสิทธิ์รับงวดนี้
   - ต้องระบุ **เหตุผล** ทุกครั้ง · ระบบเก็บค่าจากไฟล์เดิมไว้ (ดูได้ในหน้าดูตัวอย่างสลิป) · บันทึก Audit Log พร้อมยอดก่อน/หลัง
   - ตารางแสดงป้าย "แก้ไขด้วยมือ" / "เพิ่มด้วยมือ" และกรองตามที่มาได้ · สลิปที่พิมพ์ออกไม่มีเครื่องหมายแก้ไข
   - ⚠️ นำเข้าไฟล์ทับงวดเดิม = สลิปที่แก้/เพิ่มด้วยมือจะถูกแทนที่ทั้งหมด (ระบบแจ้งจำนวนก่อนยืนยัน)
5. **พิมพ์:** ทีละคน / ที่เลือก / ตามตัวกรอง (เช่น ทั้งงาน) · 1 คนต่อ A4 · เปลี่ยนชื่อ-ตำแหน่งผู้ลงนามได้ทุกครั้ง (ค่าเริ่มต้นจาก "ตั้งค่าหน่วยงาน")
   - ทำ PDF: ในหน้าต่างพิมพ์เลือก **"บันทึกเป็น PDF"** · A4 แนวตั้ง · ระยะขอบ "ไม่มี" · ปิด "ส่วนหัวและส่วนท้าย"
   - โลโก้บนสลิป (หัวกระดาษ + ลายน้ำ) ใช้โลโก้ที่อัปโหลดใน "ตั้งค่าระบบ"

### แท็บ "สลิปแบบ Manual" (ในเมนูสลิปเงินเดือน) – สลิปเพิ่มเติม แยกจากงวดที่นำเข้า
หน้าสลิปเงินเดือนมี 2 แท็บ: **งวดเงินเดือน (นำเข้า Excel)** และ **สลิปแบบ Manual**
แท็บ Manual ใช้สำหรับสลิปที่ไม่ได้มาจากไฟล์ Excel เช่น สลิปเงินตกเบิก หรือผู้ที่ไม่มีในไฟล์ (ไม่กระทบสลิปในงวดเดิม)
- **สร้างสลิปใหม่:** เลือกเดือน/ปี · หัวเรื่องสลิป (เช่น "สลิปเงินตกเบิก") · ชื่อ ประเภท สังกัด หน่วยงาน · รายการรับ-หัก · หมายเหตุ (พิมพ์บนสลิป)
  ระบบคำนวณยอดและจำนวนเงินตัวอักษรให้ และ **ออกเลขที่สลิปอัตโนมัติ** `MSปปปป-ลำดับ` (ลบแล้วเลขที่ไม่ถูกนำกลับมาใช้ซ้ำ)
- **คัดลอก:** ทำสลิปเดือนถัดไปจากใบเดิม (เลื่อนเดือนให้อัตโนมัติ) · **แก้ไข** · **ลบ** (ต้องระบุเหตุผล)
- **พิมพ์:** รูปแบบ A4 เดียวกับสลิปปกติ เปลี่ยนผู้ลงนามได้ บันทึก PDF ได้ · หัวกระดาษตั้งต้นตามงวดล่าสุดที่นำเข้า (แก้ได้ในส่วน "ส่วนหัวสลิป")
- สิทธิ์ (ชุดเดียวกับโมดูลสลิปเงินเดือน): `payroll.view` ดู · `payroll.print` พิมพ์ · `payroll.manage` สร้าง/แก้ไข/ลบ
- ข้อมูลอยู่ในตาราง `payroll_manual_slips` ปิดการเข้าถึงตรงแบบเดียวกับสลิปปกติ (ผ่าน `sfh_payroll_manual_*` เท่านั้น)

| Permission | ทำอะไรได้ | ค่าเริ่มต้น |
|---|---|---|
| `payroll.view` | เข้าเมนู ดูงวดที่เผยแพร่/ปิดแล้ว และดูสลิป | Org Admin, staff1 |
| `payroll.manage` | นำเข้า เผยแพร่ ปิดงวด ลบ และเห็นงวด "ร่าง" | Org Admin, staff1 |
| `payroll.print` | พิมพ์ / บันทึก PDF | Org Admin, staff1 |
| `payroll.export` | ส่งออก CSV | Org Admin, staff1 |

**ความปลอดภัย (ต่างจากโมดูลอื่น):** ตาราง `payroll_periods` / `payroll_slips` ปิดการเข้าถึงตรง (RLS ไม่มี Policy + revoke) –
หน้าเว็บเข้าถึงผ่านฟังก์ชัน `sfh_payroll_*` ที่ตรวจ **session token** (ออกตอน Login อายุ 8 ชม. ยกเลิกเมื่อออกจากระบบ) + สิทธิ์ + หน่วยงาน ทุกครั้ง
และบันทึก Audit Log ฝั่งฐานข้อมูล (นำเข้า / เผยแพร่ / ปิดงวด / พิมพ์ พร้อมชื่อผู้ลงนาม / ส่งออก) – ถือ anon key อย่างเดียวอ่านเงินเดือนไม่ได้
| `config.js` | ใส่ `SUPABASE_URL` และ `SUPABASE_ANON_KEY` |
| `index.html` | ตัวเว็บทั้งหมด (HTML/CSS/JS ไฟล์เดียว) |

## โมดูลงานสารบรรณอิเล็กทรอนิกส์ (e-Saraban)
คลังเอกสารราชการดิจิทัล: หนังสือราชการ (หนังสือเข้า/หนังสือส่ง), คำสั่ง/ประกาศ, ระเบียบ, บันทึกข้อความ/หนังสือเวียน, คู่มือ/แบบฟอร์ม

- **ติดตั้ง:** SQL Editor › วาง `module_saraban.sql` › Run (หลังจากรัน `database.sql` แล้ว)
- **นำเข้าเอกสารที่มีเลขแล้ว:** อัปโหลดไฟล์ → เลือกประเภท → กรอก **เลขที่หนังสือ, เจ้าของหนังสือ, ชื่อเรื่อง** (ระบบไม่ออกเลขทะเบียนเอง)
  - ชื่อเรื่องเติมให้จากชื่อไฟล์อัตโนมัติ (แก้ไขได้) · เตือนเมื่อเลขที่หนังสือซ้ำกับเอกสารประเภทเดียวกัน
  - เลขที่หนังสือไม่บังคับสำหรับระเบียบ คู่มือ และแบบฟอร์ม · ข้อมูลอื่น (ลงวันที่ ถึง/เรียน ความเร่งด่วน สาระสำคัญ คำค้น) อยู่ในส่วน "ข้อมูลเพิ่มเติม (ไม่บังคับ)"
- **ไฟล์แนบ** ได้หลายไฟล์ต่อเอกสาร (PDF, Word, Excel, PowerPoint, ZIP, รูปภาพ) ไฟล์ละไม่เกิน 20 MB · รูปภาพบีบอัดเป็น WebP อัตโนมัติ · ดาวน์โหลดได้ชื่อไฟล์ภาษาไทยเดิม · ดูตัวอย่าง PDF/รูปได้ในหน้าเว็บ
- **ระดับการเข้าถึงเอกสาร:** `สาธารณะ` (บุคคลทั่วไปดู/ดาวน์โหลดได้) · `ภายในหน่วยงาน` · `ลับ/จำกัดสิทธิ์` (เฉพาะผู้บันทึกและผู้มี `saraban.view_all`)
- **ค้นหา/กรอง** ตามเลขที่หนังสือ ชื่อเรื่อง เจ้าของหนังสือ กลุ่มเอกสาร ประเภท ปีงบประมาณ (คำนวณจากวันที่ในเอกสาร) ความเร่งด่วน · นับจำนวนเข้าชม/ดาวน์โหลด · ส่งออก CSV

| Permission | บุคคลทั่วไป | เจ้าหน้าที่ | Org Admin | Super Admin |
|---|:-:|:-:|:-:|:-:|
| `saraban.view_public` ดู/ดาวน์โหลดเอกสารสาธารณะ | ✅ | ✅ | ✅ | ✅ |
| `saraban.view` ดูเอกสารภายในหน่วยงาน | | ✅ | ✅ | ✅ |
| `saraban.create / update / delete` เพิ่ม/แก้ไข/ลบ (ของตนเอง) | | ✅ | ✅ | ✅ |
| `saraban.view_all` ดู/แก้ไขทุกฉบับในหน่วยงาน (รวมเอกสารลับ) | | | ✅ | ✅ |
| `saraban.export` ส่งออก CSV | | | ✅ | ✅ |
| `saraban.manage_types` จัดการประเภทเอกสาร | | | | ✅ |

> เจ้าหน้าที่แก้ไข/ลบได้เฉพาะเอกสารที่ตนเองบันทึก (`created_by`) ตามหลักการของระบบ หากต้องการให้แก้ไขของผู้อื่นได้ ให้มอบสิทธิ์ `saraban.view_all` รายบุคคลที่หน้า "จัดการผู้ใช้งาน"
> ⚠️ bucket `sfh-files` เป็น Public: ไฟล์ของเอกสาร "ภายใน/ลับ" เปิดได้ถ้ารู้ URL – ใช้งานจริงควรแยก bucket แบบ Private + Signed URL

## 1) ตั้งค่า Supabase
1. สมัคร/เข้าสู่ระบบที่ https://supabase.com แล้วกด **New project**
2. เมนู **SQL Editor › New query** วางเนื้อหาทั้งหมดของ `database.sql` แล้วกด **Run**
   - ควรเห็น `Success. No rows returned`
   - รันซ้ำได้ ไม่ error และไม่ลบข้อมูลที่แก้ไขไว้
3. ตรวจที่ **Table Editor**: ต้องมี 12 ตาราง และ **Storage** ต้องมี bucket `sfh-files` (Public)

## 2) ใส่ Key
เปิด **Project Settings › API** (หรือ **Connect**) แล้วคัดลอก 2 ค่ามาใส่ใน `config.js`

```js
const SUPABASE_URL = 'https://xxxxxxxx.supabase.co';
const SUPABASE_ANON_KEY = 'eyJhbGciOi...';   // anon public key (หรือ publishable key)
```

> ห้ามใช้ `service_role` key ในหน้าเว็บเด็ดขาด

ทดสอบบนเครื่อง: เปิดโฟลเดอร์ใน VS Code แล้วใช้ Live Server (หรือ `npx http-server`) แล้วเปิด `http://localhost:xxxx`
(การดับเบิลคลิกเปิด `index.html` ตรง ๆ ก็ใช้ได้ แต่แนะนำให้เปิดผ่าน server)

## 3) Deploy บน GitHub Pages
1. สร้าง Repository ใหม่ (Public) แล้วอัปโหลด `index.html`, `config.js` (และ `README.md`)
2. **Settings › Pages › Build and deployment** เลือก Source = `Deploy from a branch`, Branch = `main` / `(root)` แล้ว Save
3. รอ 1–2 นาที เปิดลิงก์ `https://<username>.github.io/<repo>/`

> anon key เป็นค่าสาธารณะ (อยู่ในหน้าเว็บอยู่แล้ว) ความปลอดภัยจริงต้องมาจาก RLS Policy – ดูหัวข้อ "ข้อควรระวัง"

## 4) บัญชีผู้ใช้เริ่มต้น
`database.sql` สร้างบัญชีเริ่มต้นให้ (superadmin, orgadmin และบัญชีเจ้าหน้าที่ตัวอย่าง) พร้อมรหัสผ่านเริ่มต้นที่อยู่ในไฟล์ SQL
- **หลังติดตั้งต้องเปลี่ยนรหัสผ่านทันที** ที่เมนู "โปรไฟล์ของฉัน → เปลี่ยนรหัสผ่าน" และปิดบัญชีตัวอย่างที่ไม่ใช้ (จัดการผู้ใช้งาน → ปิดใช้งาน)
- ห้ามเผยแพร่รหัสผ่านในเอกสาร/หน้าเว็บ · หน้า Login ไม่แสดงบัญชีทดสอบแล้ว
- รันไฟล์ SQL ซ้ำไม่เขียนทับรหัสผ่านที่เปลี่ยนแล้ว

บุคคลทั่วไป (ไม่ Login) เห็นเมนู: หน้าแรก, ข่าวสาร/ประกาศ, โปรแกรมคำนวณค่าใช้จ่ายไปราชการ

## 5) หลักการสิทธิ์ (สรุปสำหรับสอน)
- **Role** = กลุ่มผู้ใช้ · **Permission** = สิ่งที่ทำได้ รูปแบบ `<module>.<action>` เช่น `register.create`
- สิทธิ์ของผู้ใช้ = สิทธิ์ของ Role **+** สิทธิ์รายบุคคล (`user_permissions`)
- Role `guest` ใช้กับผู้ไม่ Login ได้เฉพาะ `.view_public` / `.use_public` (มี Trigger ในฐานข้อมูลบังคับอีกชั้น)
- โมดูล `register`, `payroll` ตั้ง `guest_locked = true` จึงเปิดให้ Guest ไม่ได้
- Sidebar / Bottom Nav สร้างจากตาราง `menus` + `modules` กรองด้วย Permission (ไม่ hardcode ใน HTML)
- ฟังก์ชัน RPC: `sfh_login`, `sfh_refresh_session`, `sfh_set_password`, `sfh_change_password`, `sfh_guest_menus`

## 6) วิธีเพิ่มโมดูลใหม่ในอนาคต (ตัวอย่าง: travel)
1. **SQL** – สร้างไฟล์ `module_travel.sql` (รันต่อจาก `database.sql`) ที่มี
   - ตารางข้อมูลของโมดูล (มี `org_id`, `created_by`, `created_at`, `updated_at`) + RLS 4 Policy
   - Permission ใหม่ (ถ้ามี) `insert into permissions ... on conflict (perm_key) do nothing`
   - `update modules set status = 'active', version = '1.0.0' where module_key = 'travel';`
2. **index.html** – เขียนฟังก์ชันในบล็อก `/* ===== MODULE: travel ===== */`
   ```js
   async function renderTravel(el, mod, menu) {
     if (!requirePermission('travel.use_public')) return;
     el.innerHTML = pageHeader({ title: mod.name, icon: 'plane' }) + '...';
     // ใช้ฟังก์ชันกลาง: db, logAudit, formatMoney, bahtText, formatThaiDate,
     // createDataTable, downloadCSV, compressImage, uploadFile, confirmModal, showToast
   }
   ```
3. เปลี่ยน Registry เพียงบรรทัดเดียว (ไม่ต้องแก้ Router/Sidebar)
   ```js
   travel: { render: renderTravel },
   ```
4. เพิ่มโมดูลใหม่ที่ยังไม่มีในระบบ: เพิ่มแถวใน `modules`, `menus` (menu_group = 'module') และ `permissions`
   แล้วเพิ่ม key ใน `MODULES` → เมนูจะขึ้นเองตามสิทธิ์

## 7) ข้อควรระวัง (PDPA)
Policy แบบ `USING (true)` ใช้เพื่อ **การสอน/ทดสอบเท่านั้น** ใครมี anon key ก็อ่าน/แก้ข้อมูลผ่าน REST API ได้โดยตรง
การซ่อนปุ่มในหน้าเว็บไม่ใช่ความปลอดภัยจริง ห้ามใช้กับข้อมูลการเงินและข้อมูลส่วนบุคคลจริง
หากจะใช้งานจริงให้ย้ายไปใช้ Supabase Auth/JWT + Policy ตาม `org_id`/`created_by` และทำงานเขียนผ่านฟังก์ชันที่ตรวจสิทธิ์ในฐานข้อมูล
(รายละเอียดอยู่ท้ายไฟล์ `database.sql`) และควรลบกล่อง "บัญชีทดสอบ" ในหน้า Login ออก

## 8) แก้ปัญหาที่พบบ่อย
| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| ขึ้น "ยังไม่ได้เชื่อมต่อฐานข้อมูล" | ยังไม่ได้แก้ `config.js` หรือใส่ค่าผิด |
| "ไม่พบตาราง/ฟังก์ชันในฐานข้อมูล" | ยังไม่ได้รัน `database.sql` หรือรันไม่ครบ |
| อัปโหลดรูปไม่ได้ | ตรวจ bucket `sfh-files` และ Storage Policy ในส่วนที่ 7 ของ SQL |
| Login ถูกแต่เข้าไม่ได้ | บัญชีหรือหน่วยงานถูกปิด (`is_active = false`) |
